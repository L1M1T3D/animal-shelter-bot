# Animal Shelter Bot

**Telegram-бот и REST API для приюта животных** — учебный проект SkyPro на Java и Spring Boot.

Приложение помогает посетителям получать информацию о приюте и доступных питомцах, а новым владельцам — отправлять ежедневные отчёты о состоянии животного во время испытательного срока. Сотрудники могут оформлять усыновления и просматривать отчёты через REST API.

**Стек:** Java 21 · Spring Boot 3.5.11 · Maven · Spring Data JPA · PostgreSQL · Liquibase · Telegram Bot API · JUnit 5 · Mockito · JaCoCo.

## Возможности

### Telegram-бот

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие и регистрация Telegram-пользователя |
| `/help` | Список доступных команд |
| `/animals` | Список доступных для усыновления животных (до 20 записей) |
| `/shelter` | Адрес и часы работы приюта |
| `/adopt` | Информация о подготовке к усыновлению |
| `/care` | Советы по уходу и адаптации животного |
| `/contact` | Контактные данные приюта |
| `/myadoption` | Сведения об активном испытательном сроке |
| `/report` | Начало отправки ежедневного отчёта |

После команды `/report` владелец может отправить текст и фотографию отдельными сообщениями в любом порядке либо одну фотографию с подписью. Пока отчёт не завершён, его черновик сохраняется в PostgreSQL.

### Усыновления и ежедневные отчёты

- Оформление усыновления через REST API с **30-дневным испытательным сроком**.
- Защита от повторного усыновления недоступного животного и от нескольких активных испытательных сроков у одного пользователя.
- Один полный отчёт за календарный день по одному усыновлению; повторная отправка отклоняется.
- Сохранение текста отчёта и Telegram `file_id` фотографии.
- Ежедневные напоминания владельцу (по умолчанию **10:00 по Asia/Almaty**).
- Уведомление волонтёра при отсутствии отчётов **два дня и более**, если задан `TELEGRAM_VOLUNTEER_CHAT_ID`.

> Уведомления, отправка отчётов и получение данных зависят от корректной настройки Telegram-бота и базы данных. В текущей учебной реализации у пользователя может быть только один активный испытательный срок.

## Быстрый запуск

### 1. Подготовьте окружение

Потребуются:

- **JDK 21**;
- **PostgreSQL** с доступным локальным сервером;
- **IntelliJ IDEA** или другая Java IDE;
- токен бота от BotFather, если нужна интеграция с Telegram.

Создайте базу данных в PostgreSQL:

```sql
CREATE DATABASE animal_shelter;
```

### 2. Укажите переменные окружения

В IntelliJ IDEA откройте **Run → Edit Configurations → AnimalShelterApplication → Environment variables**.

| Переменная | Назначение | Пример / значение по умолчанию |
| --- | --- | --- |
| `DB_URL` | JDBC-адрес PostgreSQL | `jdbc:postgresql://localhost:5432/animal_shelter` |
| `DB_USER` | Пользователь PostgreSQL | `postgres` |
| `DB_PASSWORD` | Пароль пользователя PostgreSQL | **Задаётся локально** |
| `TELEGRAM_BOT_ENABLED` | Включение Telegram-бота | `true` для реальной работы; по умолчанию `false` |
| `TELEGRAM_BOT_TOKEN` | Токен бота от BotFather | **Задаётся локально** |
| `TELEGRAM_VOLUNTEER_CHAT_ID` | Числовой идентификатор чата волонтёра | Необязательно |
| `SHELTER_ADDRESS` | Адрес приюта для `/shelter` | Необязательно |
| `SHELTER_HOURS` | Часы работы приюта для `/shelter` | Необязательно |
| `SHELTER_CONTACT` | Контакт для `/contact` | Необязательно |

Шаблон значений находится в `.env.example`. Сам по себе этот файл **не подгружает переменные** в IntelliJ: заполните их в конфигурации запуска или настройте загрузку через окружение отдельно.

**Никогда не добавляйте действующий токен бота и пароль PostgreSQL в Git или в примеры HTTP-запросов.**

### 3. Запустите приложение

1. Выберите JDK 21 для проекта и конфигурации запуска.
2. Откройте `src/main/java/ru/skypro/animalshelter/AnimalShelterApplication.java`.
3. Выберите конфигурацию `AnimalShelterApplication` с настроенными переменными окружения.
4. Нажмите **Run** и дождитесь строки `Started AnimalShelterApplication`.

По умолчанию приложение доступно по адресу `http://localhost:8080`.

При первом запуске Liquibase применит изменения структуры базы данных. Для проверки откройте `http://localhost:8080/api/animals` — в новой базе ожидается пустой JSON-массив `[]`.

## REST API

Базовый адрес: `http://localhost:8080`.

| Метод | Адрес | Назначение | Успешный ответ |
| --- | --- | --- | --- |
| `POST` | `/api/animals` | Создать животное | `201 Created`, ID |
| `GET` | `/api/animals` | Список животных | `200 OK`, массив |
| `GET` | `/api/animals?species=CAT` | Фильтр по виду (`CAT` / `DOG`) | `200 OK`, массив |
| `GET` | `/api/animals/{id}` | Получить животное | `200 OK`, объект |
| `PUT` | `/api/animals/{id}` | Обновить животное | `200 OK`, объект |
| `DELETE` | `/api/animals/{id}` | Удалить животное | `204 No Content` |
| `POST` | `/api/adoptions` | Оформить усыновление | `201 Created`, ID |
| `GET` | `/api/adoptions/{id}` | Получить усыновление | `200 OK`, объект |
| `GET` | `/api/adoptions?telegramId={id}` | Усыновления пользователя | `200 OK`, массив |
| `POST` | `/api/reports` | Создать полный ежедневный отчёт | `201 Created`, ID |
| `GET` | `/api/reports/{id}` | Получить отчёт | `200 OK`, объект |
| `GET` | `/api/reports?adoptionId={id}` | Отчёты по усыновлению | `200 OK`, массив |

Для создания животного передаются `name`, `species`, `available`; для оформления усыновления — `animalId`, `telegramId`; для отчёта — `adoptionId`, `description`, `photoFileId`.

Ожидаемые ошибки API: **400** — некорректный запрос, **404** — сущность не найдена, **409** — конфликт с бизнес-правилами или ограничениями данных.

Все примеры для встроенного HTTP Client IntelliJ собраны в едином файле **[`requests.http`](requests.http)**. Измените переменные в начале файла и нажимайте зелёную стрелку рядом с нужным запросом.

## Как проверить полный сценарий

1. Запустите приложение и отправьте боту `/start`, чтобы Telegram-пользователь появился в базе данных.
2. Создайте доступное животное через `POST /api/animals`.
3. Используя ID питомца и реальный Telegram ID владельца, отправьте `POST /api/adoptions`.
4. В Telegram проверьте `/myadoption`, затем отправьте `/report` → текст → фотографию (или фотографию с подписью).
5. Убедитесь, что отчёт появился в `GET /api/reports?adoptionId=...` и повторный отчёт в тот же день не принимается.

`POST /api/adoptions` и `POST /api/reports` — служебные REST-операции, а не команды Telegram. Значение `photoFileId` — идентификатор файла Telegram, а не локальный путь к изображению.

## База данных и миграции

Сущности приложения описывают приют, животных, пользователей Telegram, усыновления и отчёты. Для незавершённых Telegram-отчётов используются черновики.

Схема базы развивается через Liquibase:

```text
src/main/resources/db/changelog/
├── 001-init.sql
├── 002-reports.sql
└── db.changelog-master.yaml
```

Главный changelog подключает обе миграции. **Не изменяйте содержание `001-init.sql`, если миграция уже применялась:** это может вызвать ошибку контрольной суммы Liquibase. Для новых изменений создавайте следующие миграции.

## Тестирование

В проекте используются JUnit 5, Mockito, тесты Spring MVC и JPA. Полная проверка через Maven Wrapper:

```powershell
.\mvnw.cmd clean verify
```

Если Maven не видит установленный JDK, проверьте `JAVA_HOME` и Java 21 в конфигурации IntelliJ.

**Примечание для Windows:** _(учитесь на ошибках автора...)_ системное значение `JAVA_TOOL_OPTIONS=-Dfile.encoding=IBM866` может повредить путь с кириллическими символами при запуске Java-агента JaCoCo. В PowerShell его можно временно убрать для текущего терминала:

```powershell
Remove-Item Env:JAVA_TOOL_OPTIONS -ErrorAction SilentlyContinue
```

Если агент JaCoCo мешает запуску тестов, можно выполнить только проверки без измерения покрытия:

```powershell
.\mvnw.cmd "-Djacoco.skip=true" verify
```

Это **не заменяет** проверку покрытия. При успешном запуске JaCoCo HTML-отчёт формируется в `target/site/jacoco/index.html`. Процент покрытия ДЗ № 3 не заявляется без отдельного измерения.

## Организация разработки

Проект разрабатывается индивидуально. Используемые ветки:

- `main` — стабильная версия;
- `dev` — основная ветка разработки;
- `release` — подготовка релиза;
- `feature/*` — отдельные задачи и этапы.

Изменения предлагаются к объединению через Pull Request. Рабочие заметки и планирование ведутся в **Notion**; технические материалы также хранятся в `docs/`.

## Ограничения учебной версии

- Административные REST-эндпоинты не защищены полноценной авторизацией. Не публикуйте их в интернете без настройки безопасности.
- Информация о приюте задаётся через переменные окружения; демонстрационные данные необходимо заменить реальными перед использованием.
- Эта версия поддерживает одного активного усыновлённого питомца на Telegram-пользователя и не заменяет полноценную систему учёта приюта.
